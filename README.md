# OpenTherm-термостат на ESP32-S3 для Smart Life (Tuya)

Прошивка управляет электрокотлом BAXI (18 кВт) по OpenTherm и работает как термостат
в приложении Smart Life. Регулирование, расписание и защита выполняются **на самом
устройстве**; облако — только пульт и редактор настроек. Без интернета устройство
продолжает работать по последним настройкам.

- SDK: [TuyaOpen](https://github.com/tuya/TuyaOpen) v1.9 (платформа ESP32, ESP-IDF 5.4)
- Продукт Tuya: «Opentherm esp32», PID `n7d4xowvbfcqlgo9`, категория `wk`, дата-центр Central Europe
- Плата: адаптер OpenTherm_ESP32S3 rev 4 (`README.pdf`) с модулем ESP32-S3 SuperMini

## Железо

| | |
|---|---|
| Модуль | ESP32-S3FH4R2: 4 МБ флеш, 2 МБ quad PSRAM, только родной USB (Serial/JTAG) |
| OpenTherm TX / RX | GPIO13 / GPIO12 (адаптер Ihor Melnyk на PC817) |
| DS18B20 №1 / №2 | GPIO10 / GPIO11 (у каждого своя линия, без поиска адресов) |
| BMP180 (I²C) | SDA GPIO8, SCL GPIO9 — пока не используется |
| Кнопка | BOOT (GPIO0) |
| Светодиод | WS2812 на GPIO48, порядок байтов GRB |

Пины и полярности меняются в `Kconfig` (раздел «Opentherm ESP32-S3 hardware»).

## Сборка и прошивка

Нужен TuyaOpen в `%USERPROFILE%\TuyaOpen` (или переменная `OPEN_SDK_ROOT`).

```powershell
.\build.ps1                 # сборка
.\build.ps1 clean           # полная очистка — после правки Kconfig, sdkconfig.overlay, app_default.config
.\build.ps1 flash           # сборка + прошивка COM5 (сам переводит чип в загрузчик, 3 попытки)
.\build.ps1 flash-manual    # если автоматически не вышло: BOOT + RESET вручную, потом эта команда, потом RESET
.\build.ps1 log             # лог устройства, 20 с, без перезагрузки (USB)
.\build.ps1 ota [IP]        # сборка + обновление по Wi-Fi (без IP — поиск платы в локальной сети)
.\build.ps1 cmd "status"    # команда консоли на плате по Wi-Fi + свежий лог
.\build.ps1 rlog            # лог платы по Wi-Fi (последние ~12 КБ)
.\build.ps1 webpass         # адрес и пароль веб-интерфейса
```

**Локальный HTTP-сервер платы** (порт 8080), доступен из той же сети:
- `http://<IP платы>:8080/` — веб-интерфейс: состояние, котёл, датчики, энергия и формы
  настроек и расписания; `/log` — лог. Вход: `admin` + пароль из `.\build.ps1 webpass`.
- Обновление по Wi-Fi (`POST /ota`) и консоль (`POST /cli`) — для `build.ps1`, по токену.
- Пароль и токен лежат в `include/ota_secret.h` (создаёт `build.ps1`, в git не попадает).
- Новая прошивка грузится «на проверке» и подтверждает себя через 60 с работы **с облаком
  на связи**; при сбое, зависании или без облака 5 минут — откат на предыдущую.

Почему не `tos.py flash`: `tyutool` на родном USB обрывает запись. Плата описана прямо в
проекте, SDK не правится:
- `Kconfig` — 4 МБ флеша (`PLATFORM_FLASHSIZE_4M`), консоль на USB-JTAG, пины, пределы регулятора;
- `sdkconfig.overlay` — quad PSRAM и откат прошивки при неудачном OTA; подмешивается через `SDKCONFIG_DEFAULTS` в `build.ps1`;
- `esp_components/ot_port` — компонент ESP-IDF (TuyaOpen подключает `esp_components/` сам).

## Лицензия и сопряжение

Нужна **лицензия TuyaOpen** (UUID + AuthKey). Ключи в git не попадают:
- **консоль:** `tos.py monitor -p COM5`, затем `auth <UUID> <AUTHKEY>` (хранится в KV платы, приоритетнее файла);
- **или файл:** `include/tuya_config_secrets.h` по образцу `.example` (файл в `.gitignore`).

Сопряжение — только BLE: Smart Life → «+» → «Добавить устройство», Wi-Fi 2,4 ГГц.
Если телефон не находит устройство — проверить разрешения Smart Life «Устройства
поблизости» и точную геолокацию, перезагрузить телефон (именно это помогло на Tecno).

## Точки данных (DP)

Из модели продукта (Tuya OpenAPI `/v2.0/cloud/thing/{id}/model`), см. `include/dp_ids.h`:

| ID | Код | Тип | Устройство |
|---|---|---|---|
| 1 | `switch` | bool | вкл/выкл отопления (защита от замерзания работает всегда) |
| 2 | `temp_set` | value ×0,1 °C, 5–35 | уставка комнаты для `manual`/`home` |
| 3 | `temp_current` | value, целые °C | температура управляющего датчика |
| 4 | `mode` | enum | `auto` расписание (уставки подачи), `manual` ручная уставка подачи, `home` комната на `temp_set`, `leave` 16 °C |
| 5 | `work_state` | enum | `heating` ТЭНы включены, `warm` запрос тепла, `idle` |
| 11 | `fault` | bitmap | бит 0 датчик, бит 2 котёл (ошибка или нет связи OpenTherm) |
| 15 / 16 | `upper_temp` / `lower_temp` | value ×0,1 °C | пределы уставки |
| 28 | `week_program_2` | raw, 112 байт | недельное расписание: точки = уставки подачи котла (< 20 °C — выкл.) |
| 10 | `work_power` | value, W | оценка мощности: модуляция × 18 кВт |
| 101 | `boiler_temp_set` | value, °C 20–80 | уставка подачи в ручном режиме |
| 102 | `flow_temp` | value, °C | фактическая подача котла |
| 103 / 104 | `temp_sensor1/2` | value ×0,1 °C | DS18B20 на J2 / J3 |
| 105 | `temp_board` | value ×0,1 °C | BMP180 на плате (завышает) |
| 106 | `pressure` | value, hPa | BMP180 |
| 107 | `ele_total` | value ×0,01 kWh | оценка потреблённой энергии (нарастающий итог) |

**Расписание** (`src/app/schedule.c`): 7 дней с понедельника × 4 точки × 4 байта —
час, минута, температура (2 байта big-endian, ×0,1 °C). Температура точки действует до
следующей, в том числе через полночь. Формат подтверждён пакетом из редактора
Week Program 2 в Smart Life (воскресенье — 7-й день); лог `dp rx id:28 type:RAW` печатает байты.

## Регулирование и защита

Ядро 1: мастер OpenTherm (обмен раз в секунду: ID0 статус + включение отопления, ID1
уставка подачи, ID25 подача, по очереди ID17 модуляция и ID5 коды ошибок) и регулятор
(раз в 2 с). Ядро 0: сеть Tuya, датчики, кнопка, светодиод, supervisor.

- Цель: `switch=off` → 5 °C (защита от замерзания); `auto` → расписание, а если время
  неизвестно → `temp_set`; `leave` → 16 °C.
- PI-регулятор → уставка подачи 25–75 °C (`HEAT_FLOW_*` в `Kconfig`, для тёплого пола снизить максимум).
- Нет датчика (нет показаний дольше 2 мин) → фиксированная подача 45 °C, не максимум.
- Нет связи с котлом (5 обменов подряд) или ошибка котла → бит в `fault`.
- Нет Wi-Fi/облака → работа по сохранённым настройкам. Отвязка в приложении сбрасывает
  только сеть, настройки отопления остаются. До первого сопряжения — 20 °C, `manual`.
- Watchdog: supervisor кормит аппаратный сторож (10 с) только пока живы задачи котла и
  регулятора; зависание сети плату не перезагружает.
- OTA: новая прошивка подтверждается через 60 с нормальной работы, иначе откат.

Поведение котла при потере связи OpenTherm — **проверить на реальном котле** и записать сюда.

## Светодиод и кнопка

| Светодиод | Значение |
|---|---|
| сиреневый ровно | кнопка удерживается ≥ 10 с — при отпускании сброс настроек отопления |
| голубой ровно | кнопка удерживается 5–10 с — при отпускании отвязка (Wi-Fi + привязка) |
| красный, 1 Гц | ошибка: датчик, котёл или связь OpenTherm |
| синий, быстро | ждёт сопряжения |
| жёлтая вспышка раз в 2 с | нет облака (отопление работает) |
| оранжевый | в сети, ТЭНы включены |
| зелёный | в сети |

Кнопка срабатывает **при отпускании** — плата не перезагружается с зажатым GPIO0.

## Консоль (CLI) и стенд без котла

Консоль на COM5 (`tuya>`): `status`, `heat on|off`, `set 21.5`, `mode auto`, `limits 5 30`,
`sched` / `sched set 1 1 06:30 21.5` / `sched hex`, `time <UTC epoch>`, `sensor`,
`ot log on`, `ot raw 0 25 0`, `led` (тест цветов), `wdt stall boiler` (тест watchdog),
`report` (отправить все DP), `unbind`, `factory`, `auth`.

**Эмулятор котла** — только на голом модуле, не на плате адаптера (он управляет GPIO12 как
выходом): `sim start bare`, `sim speed 60`, `sim fault 42`, `sim mute on`. Модель: электрокотёл
18 кВт (6 ступеней по 3 кВт) + дом; эмулятор отвечает мастеру по тем же пинам через
внутреннюю петлю GPIO, температура комнаты идёт в датчик №1.

## Известные особенности

- Автоматический переход в загрузчик по USB на этом ПК иногда не срабатывает
  (`Write timeout`) — тогда `flash-manual`. После неудачной попытки USB может «залипнуть»
  до переподключения кабеля; прошивка при этом работает.
- В SDK есть фоновая синхронизация DP: значения, которые прошивка ещё не отправляла
  (`work_power`, `temp_current` без датчика), уходят в облако как 0.
- Ошибка TuyaOpen: bitmap-DP через `tuya_iot_dp_obj_report` отбрасывается всегда (`bitmap check fail`) — `fault` шлётся через `tuya_iot_dp_report_json`.
- Расписание из Smart Life приходит по локальной сети напрямую с телефона — в журнале команд облака его не видно.
- Макросы логов TuyaOpen не проверяют формат: `tal_system_get_millisecond()` 64-битный — приводить явно.
